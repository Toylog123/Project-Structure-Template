# 文件分类与命名规范

> 统一全项目文件的**分类与命名**：不同实验、不同版本、不同类型分开存放，方便查找，**不大批混块**。

## 一、总则

1. **按类别分类**：不同实验 / 版本 / 类型分开存放，不合并。
2. **命名含标识**：文件名带图号 / 实验名 / 日期 / 版本，便于搜索定位。
3. **不散落**：禁止根目录散落文件、大批文件混在单目录、临时文件入正式目录。

## 二、各目录分类约定

| 目录 | 分类方式 | 命名规范 |
|------|---------|---------|
| `code/src/` | 按模块 | `<模块名>/` |
| `code/tests/` | 按测试对象 | `test_<对象>.py` |
| `code/scripts/` | 按用途 | `<用途>.sh / .py` |
| `experiments/` | 按实验 | `<实验名>/`（每实验一个目录） |
| `evidence/` | 域 → 实验 → 日期 | `<域>/<实验>/<YYYYMMDD>_r<N>/` |
| `versions/` | 按版本（基线） | `<基线ID>/` |
| `figures/` | 图号 + 阶段 | `fig<N>_<名称>`；final / sources / candidates 分开放 |
| `figures/plot_specs/` | 每图一份 | `fig<N>_<名称>_data.md` |
| `figures/drawing_prompts/` | 每图一份 | `fig<N>_<名称>_prompt.md` |
| `review_rounds/` | 按审稿轮次 | `r<N>_<YYYYMMDD>/` |
| `data/` | 按数据集阶段 | manifests / raw / derived / schemas |
| `project_docs/` | 按文档类型 | 既定文件名（见 README） |
| `skills/` | 按技能 | `<技能名>/` |

## 三、命名与查找

1. **日期统一**：`YYYYMMDD`；**版本**：基线 ID；**轮次**：`r<N>`。
2. **查找路径**：目录 → 子目录 → 文件名；或搜索图号 / 实验名 / 日期。
3. 每个分类目录有 README 说明放什么（已建立），按说明归类。
4. 新建内容时先看目录 README，归入正确分类，不另起散乱位置。

## 四、防混块规则

1. **不同实验**：`experiments/` 与 `evidence/` 按实验名分目录，不合并。
2. **不同版本**：`evidence/` 按日期建包，`versions/` 按基线分目录，不覆盖旧包。
3. **不同图 / 表**：每图一个 `fig<N>` 标识，草图和定稿分 `candidates/` / `final/`。
4. **临时文件**：放 `scratch/`（git-ignored），不入正式目录。
5. **大批文件**：单目录文件过多时按子分类再拆分（如按年份、按批次）。
6. 归档 / 版本 / 证据的具体位置见 `project_docs/ARCHIVE_POLICY.md`。

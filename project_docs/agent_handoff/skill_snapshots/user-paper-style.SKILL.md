# 项目文档写作规范（Docs Style）

与 `academic-paper` / `academic-pipeline` 配合使用，作为项目本地补充。

## 适用范围

本规范适用于**所有项目文档写作**，取决于用户要写什么：

- 学术论文（`paper/`）：中英术语 / GB·T 7714 / 消融实验
- 技术说明 / 设计文档 / 报告（`docs/`、`project_docs/`、`code/src/DESIGN.md`）
- 交接文档 / 经验记录 / 周报

**通用原则**（证据校验、术语统一、写作语言、自检）适用于所有类型；**论文专属规则**（引用格式、消融实验）在论文场景启用。

## 一、证据强制校验（写任何文档前必须做）

**写任何声明前，先校验证据；证据不足不写，宁可标注也不编造。**

1. 每个实验 / 数据 / 数字必须能追溯到 `project_docs/evidence/` 中的证据包或具名基线。
2. **禁止编造**实验、数据、引用、结果——这是不可逾越的红线。
3. 无法核实的引用或数据，标注 `[待核]` 并列出待办，不进入最终正文。
4. 证据分级：已读原文 / 已读摘要 / 仅有元数据 / 待核验。只有前两级可作结论依据。

## 二、引用核查（引用前逐条核对）

1. 每条引用尽量定位到原文（页码 / 章节）。
2. 区分**直接引用**（逐字，超长加引号）与**间接引用**（转述）。
3. 拒绝三类错误：幽灵引用（引用了但原文不存在）、转引错误（引二手非原始）、断章取义。
4. 数据引用精确到数据库名、变量名、样本时间范围。
5. 输出核查结果：已核实 / 待核 / 无法核实，诚实标注。

## 三、引用格式（论文场景：GB/T 7714）

1. 论文参考文献按 **GB/T 7714-2015** 著录；全文统一。
2. 中英文文献、期刊 / 会议 / 学位论文条目格式符合国标。
3. 正文引用标注与文末文献表一一对应，无孤立引用。
4. 技术文档引用从简但必须真实、可溯源。

## 四、格式自检清单（交付前逐项过）

- [ ] 每个数字都能指向证据包 / 基线
- [ ] 无编造实验、数据、引用
- [ ] 术语统一（`docs/GLOSSARY.md`；论文场景还须中英对照）
- [ ] 引用真实可溯源（论文场景 GB·T 7714）
- [ ] 全角中文标点，中英文间无多余空格
- [ ] 图表只保留支撑论点的指标
- [ ] 数字口径标明：软件复现 / 策略复现 / RTL 回放 / 工具报告 / 实测

## 五、写作语言

- 中文优先；正文写成成熟文档，不写版本迭代、开发过程或防御性说明。
- 避免 AI 套话：禁用机械过渡词（首先 / 其次 / 此外）、空壳强调句（值得注意的是）、空洞修饰词。
- 用语义衔接替代模板衔接，用数据事实替代形容词。

## 六、历史版本数据的使用（论文场景：消融实验）

1. **正式结果用最新版本**：论文主结果、主结论一律基于最新版本（当前活跃基线）的数据。
2. **历史版本数据 → 消融实验**：旧版本 / 历史配置的数据可用于**消融实验或对比分析**，以支撑某设计决策。
3. **不写"版本"字眼**：正文不出现"版本 1 / 旧版本"等开发性表述；消融变体用**功能差异命名**。
4. **数据真实**：数字来自对应版本 / 配置的真实证据包，交叉表记录。
5. **口径可比**：消融对比与正式结果的运行条件、输入、样本需一致可比。

## 七、术语同步

- 修改任何文档时若术语 / 译名 / 缩写改变，**必须同步更新**术语表：`docs/GLOSSARY.md`（项目级），论文场景还须更新 `paper/GLOSSARY.md`（中英两版）。
- 顺序：先改术语表，再改文档（或同一编辑内完成）；定稿时核对无旧译名残留。

## 八、审稿工作流（多智能体 + 多 skill）

审稿迭代时**调用多智能体**，每个智能体用不同的审稿 skill 独立审稿，讨论综合后修改。

**项目审稿 skill**：

| skill | 视角 |
|-------|------|
| `nature-reviewer` | 审稿人视角独立评审 |
| `academic-paper-reviewer` | 7-agent 同行评审模拟 |
| `nature-ref-verifier` | 引用真实性核查 |
| `nature-response` | 审稿回复组织 |
| `user-paper-style` | 项目格式 / 术语 / 证据规范 |

**流程**：

1. **多智能体并行审稿**：派发多个智能体，各用不同 skill 独立审稿（如 A→`nature-reviewer`，B→`academic-paper-reviewer`，C→`nature-ref-verifier`，D→`user-paper-style`）。
2. **收集意见**：汇总各智能体发现（缺陷 / 澄清 / 建议），标注来源 skill。
3. **讨论综合**：对照意见找共性与分歧，综合成一份审稿行动清单。
4. **修改**：按「优先补实验 / 完善设计，而非降级描述」处理（见 `paper/zh/responses/RESPONSE_TEMPLATE.md`）。
5. **每轮归档**：建 `paper/zh/review_rounds/r<N>_<日期>/`，归档该轮意见、回复、修改前论文。
6. **一致性检查**：术语 / 证据 / 交叉表，再写回复（`nature-response`）。

## 九、绘图分工

| 图类型 | 由谁画 | 方式 |
|--------|--------|------|
| 数据图（定量折线图、统计图、曲线） | AI 用 `nature-figure` 技能 | 脚本生成，数据来自证据包，**可复现** |
| 机制图（系统结构图、流程图、硬件结构图） | **详细设计提示词（结构示意）→ 草图 → 用户手工画最终版** | AI 给出含结构示意的提示词 + 草图，用户按提示词绘制 |

- 数据图：必须可复现（脚本 + 数据源），按 `nature-figure` 规范；**每张图填数据来源记录**（`figures/plot_specs/DATA_SOURCE_TEMPLATE.md`，含基线/配置/口径），防弄混版本与配置。
- 机制图：AI 先写**详细设计提示词**（见 `paper/zh/figures/drawing_prompts/MECHANISM_FIGURE_PROMPT_TEMPLATE.md`，含模块 / 连线 / 数据流 / 层次结构示意），并出草图放 `candidates/`；论文中放草图占位，**最终由用户按提示词手工绘制**，源文件存 `sources/`、定稿存 `final/`。

## 十、写作红线：版本代号与过程性语言

论文正文**禁止**：

1. **工程版本代号**：`v1.0 / v2.0`、基线 ID（如 `R3-20260731`）、审稿轮次（`r1 / r2`）、commit hash、迭代编号——正文一律不出现。
2. **过程性语言**："我们修改了 / 改进了""第一版 / 后续版本""开发中 / 迭代中""这轮 / 上轮""重构后 / 修复后"——用结果性、静态的表述替代。
3. **文件路径**：`project_docs/evidence/...`、`experiments/...`、`code/...` 等工程路径——**论文正文一律不写**。论文数字与证据的路径映射统一在单独文件（`project_docs/evidence/CROSSWALK_TEMPLATE.md` 交叉表）记录，论文只写数字 / 结论。

**替代方式**：

- 用**功能 / 设计差异**描述不同实现（如"含反馈回路的版本"→"带反馈回路的设计"），不用版本号。
- 用"**所提方法 / 系统 / 框架**"指代最终方案，不用"我们之前的版本"。
- 呈现的是**最终成熟结果**，不叙述开发过程、修订历史或迭代。
- 涉及不同配置 / 消融对比时，用**配置 / 特性命名**（`w/o 模块A`、`baseline-XX`），不用版本号。

## 十一、术语审查（业界译名 + 防直译）

中文论文术语审查是重点，尤其针对**业界有认可英文词汇**的技术术语：

1. **业界认可译名**：技术术语优先采用业界 / 期刊 / 标准认可的中文译名（对照 `paper/GLOSSARY.md`、参考文献、GB/T 标准），不自行生造。
2. **防生硬直译**：逐句检查全文是否有**生硬直译**——英文概念直译成中文后别扭、不通顺或不专业（如 golden implementation 直译"金牌实现"），改为规范通顺的译法。
3. **审查时机**：每次论文修订 / 审稿时，**全文扫查**英文术语与直译情况。
4. **修正同步**：修正译名后同步术语表（先改表再改正文，见第七节），中英两版一致。
5. **配合语境斟酌**：翻译配合语境——同一英文概念在不同语境下可能需用不同中文表达（视上下文强调角度、搭配通顺度），结合语境选最贴合含义 / 最通顺的译法；核心专有术语仍保持全文统一（见第七条）。
6. **中译英同样审查**：中文论文转英文时，同样逐条审查——中文术语用**业界认可的英文标准术语**（对照 `paper/GLOSSARY.md` 英文列、参考文献、IEEE/ACM 通用用语），不机械直译中文；术语检查清单对中英两版都适用。
7. **术语库维护是关键**：术语审查的准确性依赖术语库（`paper/GLOSSARY.md` 中英对照 + `docs/GLOSSARY.md` 口径）。维护要求：
   - 新增术语及时登记（含业界认可译名、缩写、解释、**中英双向对照**）；
   - 审查中确定的译名**写回术语库**，避免下次重审；
   - 中译英 / 英译中都有依据；
   - 定期核对业界 / 期刊认可的译法。

**审稿时的术语检查清单**：

- [ ] 英文技术术语是否用业界认可中文译名
- [ ] 全文是否有生硬直译（读起来别扭的）——逐个修正
- [ ] 同一概念全文是否统一译名
- [ ] 修正后是否同步 `paper/GLOSSARY.md`

# 版本管理

## 一个版本 = 什么

版本由**具名基线**定义，是「论文 + 源码 + 测试 + 证据」的绑定，四者必须一致：

| 要素 | 由谁决定 | 存放 |
|------|----------|------|
| 论文 | 基线文档声明的主稿件 | `paper/zh/manuscript/` |
| 源码 | git commit / tag / manifest | `src/` |
| 测试 | 随源码演进的测试（与源码同 commit） | `tests/` |
| 证据 | 不可变证据包 | `project_docs/evidence/` |

## 代码多版本怎么管（核心）

**代码的所有版本都由 git 承载，绝不复制目录手工维护多版本。**

- 每个 git commit = 一个不可变的历史版本（含当时的源码 + 测试脚本），随时可回到任一版本。
- 中间开发版本：自然演进，用 commit 引用即可。
- 里程碑版本：打 tag（`git tag <基线ID>`），tag 即命名版本。
- 冻结基线时，用 manifest 记录「源码 + 测试 + 证据」的 SHA-256 清单，把四者锁定。

### 测试脚本版本

- 测试随代码在同一仓库演进，属于同一个 commit——**测试永远绑定它所在 commit 的源码**。
- 需要按版本区分时：在测试文件内注释标明适用基线，或 `tests/` 下按版本分子目录（如 `tests/r3/`）。
- 冻结基线时，manifest 把测试文件 hash 一并记录，确保「这段代码用的正是这套测试」。

## 何时新建版本

- 功能门完整通过并**独立验证**后。
- 论文大改（需重新声明基线）。
- 证据重做（新建证据包）。

## 多版本共存

- 旧基线标记 `superseded` 后**不可变**，作为历史参照保留。
- git 历史天然并存所有代码/测试版本，不占额外空间、不复制目录。
- 新基线取代旧基线：先过完整功能门 + 独立验证。
- **禁止**：复制目录手工维护多版本；把旧基线数据拼进新包；用工作树名 / 运行目录名当版本；修改已冻结的证据包。

## 当前版本声明

接管者从以下三处读取"当前版本"：

1. `project_docs/baselines/BASELINE_INDEX.csv` 中 `status=active` 的行。
2. `project_docs/agent_handoff/START_HERE.md` 的「活跃基线」。
3. `.codex-handoff.json` 的 `current_baseline` 字段。

## 版本与 git

- 基线确定后打 tag：`git tag <基线ID>`。
- 分支 / 工作树是**执行环境**，不是版本；只有基线能定义版本。

# Paper Writing Style（中文科技论文）

与 `academic-paper` / `academic-pipeline` 配合使用，作为项目本地补充。

## 一、证据强制校验（写论文前必须做）

**写任何声明前，先校验证据；证据不足不写，宁可标注也不编造。**

1. 每个实验 / 数据 / 数字必须能追溯到 `project_docs/evidence/` 中的证据包或具名基线。
2. **禁止编造**实验、数据、引用、结果——这是不可逾越的红线。
3. 无法核实的引用或数据，标注 `[待核]` 并列出待办，不进入最终正文。
4. 证据分级：已读原文 / 已读摘要 / 仅有元数据 / 待核验。只有前两级可作结论依据。

## 二、引用核查（引用前逐条核对）

1. 每条引用尽量定位到原文（页码 / 章节）。
2. 区分**直接引用**（逐字，超长加引号）与**间接引用**（转述）。
3. 拒绝三类错误：幽灵引用（引用了但原文不存在）、转引错误（引二手非原始）、断章取义。
4. 数据引用精确到数据库名、变量名、样本时间范围。
5. 输出核查结果：已核实 / 待核 / 无法核实，诚实标注。

## 三、引用格式（GB/T 7714）

1. 参考文献按 **GB/T 7714-2015** 著录；全文统一。
2. 中英文文献、期刊 / 会议 / 学位论文条目格式符合国标。
3. 正文引用标注与文末文献表一一对应，无孤立引用。

## 四、格式自检清单（投稿前逐项过）

- [ ] 每个数字都能指向证据包 / 基线
- [ ] 无编造实验、数据、引用
- [ ] 引用格式 GB/T 7714 统一，文内与文末对应
- [ ] 无幽灵引用 / 转引错误 / 断章取义
- [ ] 全角中文标点，中英文间无多余空格
- [ ] 术语以 `paper/GLOSSARY.md` 为准，中英对照一致
- [ ] 图表只保留支撑论点的指标，图内无标题 / 图号 / 水印
- [ ] 数字口径标明：软件复现 / 策略复现 / RTL 回放 / 工具报告 / 实测

## 五、写作语言

- 中文稿优先；正文写成成熟论文，不写版本迭代、开发过程或防御性说明。
- 避免 AI 套话：禁用机械过渡词（首先 / 其次 / 此外）、空壳强调句（值得注意的是）、空洞修饰词。
- 用语义衔接替代模板衔接，用数据事实替代形容词。

## 六、历史版本数据的使用（消融实验）

1. **正式结果用最新版本**：论文主结果、主结论一律基于最新版本（当前活跃基线）的数据。
2. **历史版本数据 → 消融实验**：旧版本 / 历史配置的数据可用于**消融实验或对比分析**，以支撑某设计决策（如移除某模块、不同参数配置的效果）。
3. **不写"版本"字眼**：正文不出现"版本 1 / 第 2 版 / 之前版本"等开发性表述；消融变体用**功能差异命名**（如 `w/o 模块A`、`baseline-XX`、`variant-Y`）。
4. **数据真实**：消融实验的数字必须来自对应版本 / 配置的真实证据包，并在 `project_docs/evidence/` 交叉表记录。
5. **口径可比**：消融对比与正式结果的运行条件、输入、样本需一致可比，避免被误读为同一基线。

## 七、术语同步

- 修改论文时若术语 / 译名 / 缩写改变，**必须同步更新** `paper/GLOSSARY.md`（中英两版）。
- 顺序：先改术语表，再改论文正文（或同一编辑内完成）；修订定稿时核对无旧译名残留。

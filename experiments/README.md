# 实验

本目录是实验定义、负载配置与编排代码的长期归属地。**结果证据不放在这里**，归 `project_docs/evidence/`。

每项实验应说明：

- 基线版本（绑定哪份代码 / 基线）
- 输入清单（数据来源、manifest）
- 命令（如何运行）
- 期望输出
- 证据去向（`project_docs/evidence/` 中的目标路径）
- **反驳性测试计划（自杀式测试）**：什么结果会推翻本主张？最强竞争基线、失效场景、不利初始条件各是什么？这些测试在实验阶段**最先**运行

## 结果不符预期时的归因

结果异常时**先归因再下结论**，不急于否定方案：

1. 逐层排查：复现 → 校验输入 / 数据 → 检查实现 → 对照设定假设。
2. 区分问题层次：实现 bug（修复复跑，想法仍成立）/ 设定缺陷（确认想法本身不成立才调整）/ 环境问题 / 数据问题。
3. 实现问题不否定原方案；设定问题才调整或放弃。
4. 归因结论写入 `docs/EXPERIENCE.md` 与实验记录（`LOGS.md`）。

## 实验复用历史（先查既往）

推进实验前先查：

- 历史版本：`versions/`（已冻结的完整快照）
- 既有证据：`project_docs/evidence/`（已做过的实验与结果）
- 经验库：`docs/EXPERIENCE.md`（踩坑与解法）
- git 历史：`git log`（之前提交的代码 / 脚本）

已推进过的实验 / 脚本可**适配复用**，不重新搭建；复用前校验来源版本、输入、口径是否适用当前需求。

建议结构（按需创建，避免冗余）：

```text
experiments/
|- case_a/            # 实验 A
|- case_b/            # 实验 B
`- common/            # 公共工具 / 配置
```

## 每次运行的记录（防混淆）

- 每次运行**必记**：实际配置（参数 / 版本 / 输入 / 时间）、结果；**配置与结果一一对应**。
- 引用任何数字前**实际打开**证据文件确认，不凭印象 / 记忆。
- 配置变更时明确标注，不与旧配置的结果混用。

## 实验 → 论文追溯链路（写论文时如何定位实验文件）

写论文时，每个数字 / 结论按 4 步定位到对应实验：

```text
① 论文数字 / 结论
   ↓ 查交叉表
② project_docs/evidence/CROSSWALK_TEMPLATE.md   ← 论文位置 → 证据包路径
   ↓ 打开证据包
③ project_docs/evidence/<域>/<实验>/<日期>/      ← 自包含：README + 原始输出 + hash
   ↓ 追溯实验定义
④ experiments/<case>/                            ← 基线 / 输入 / 命令（可复现）
```

- 每个证据包登记到 `project_docs/evidence/INDEX.md`。
- 论文数字必须等于交叉表登记的**证据数字**（投稿前逐行复核）。
- 找不到证据包的数字**不得写入论文**（见 `chinese-paper-style` 证据强制校验）。

## 多级目录结构（每级一个维度）

实验定义按 **版本 → 类型 → 实验** 多级组织：

```text
experiments/
└── v1/                    # 一级：版本
    ├── rtl/               # 二级：类型
    │   └── example_case/  # 三级：实验（config / scripts / README）
    └── power/
        └── hit_rate/
```

详见 `project_docs/FILE_ORGANIZATION.md`。

## 实验登记（避免重复做）

- **做新实验前**：查 `project_docs/evidence/EXPERIMENT_REGISTRY.md` + `evidence/`，确认未做过（同版本 / 同配置 / 同输入）。
- **每次实验完成后**：登记一行到登记表（含实验定义路径 + 证据包路径）。
